# Security and compliance controls, one provision at a time: NIST SP 800-53, SP 800-171, the SSDF, the Cybersecurity Framework 2.0 and the HIPAA Security Rule in their own words

Every control in NIST SP 800-53 Rev 5, every requirement in NIST SP 800-171 Rev 3 (the CMMC baseline), every practice and task in the NIST Secure Software Development Framework (SP 800-218), every category and subcategory of the NIST Cybersecurity Framework 2.0, and every paragraph of the HIPAA Security Rule, cut one provision at a time, each with the publisher's own words as the record's quote. One record is one obligation: a control with five lettered statements becomes five records, keyed the way the publisher cites them (SC-28, SC-28(1), AC-2a, 03.01.01.c.02, PO.1.1, GV.OC-01, 164.312(a)(2)(iv)), so a reader or an agent that has been handed a control number gets that control's text and nothing else. Answers 'what does NIST SP 800-53 SC-28 require', 'what does 800-171 03.05.03 say about multi-factor authentication', 'what does SSDF PW.7.2 require of code review', 'what is CSF 2.0 GV.OC-01', 'what does HIPAA 164.312(a)(2)(iv) actually say about encryption', 'which published controls cover audit logging', and 'what is the organization-defined parameter in AC-12'. The hard part is not finding the documents — NIST publishes all four of its frameworks as machine-readable OSCAL and the eCFR publishes the rule as XML — it is that they are published as whole documents, so a coding assistant asked to implement 'SC-28' or 'PW.7.2' either reads a 1,200-page catalogue or guesses. This dataset is the retrieval layer: provision in, the publisher's sentence out. It does not say how to implement anything, and it never says that any system is compliant; the provision's own text is the whole of what is published here. NIST's machine-readable text leaves a placeholder where a value is the organisation's to decide ('Protect the {{ insert: param, sc-28_odp.01 }} of ...'), so every record that carries one also carries the same sentence with each placeholder resolved from the catalogue's own parameter labels and kept in square brackets — '[Selection (one or more): confidentiality; integrity]' — which is how NIST's own HTML rendering reads, and which is a sentence a person or a coding assistant can actually use. The verbatim text, placeholders and all, stays on the record as the evidence. A provision its publisher has withdrawn is not here at all, whether or not the publisher left its old text in the file. SOC 2, ISO 27001 and PCI DSS are deliberately absent: that text is sold under licence by the bodies that write it and may not be republished, and the licence read of 2026-11-23 found no public mapping of the SOC 2 Trust Services Criteria to fall back on either.

Every record carries `source` (the page it came from) and `source_quote` (the exact line on that page which states it), so any value here can be checked without asking us. Where a source does not state something the row is omitted rather than guessed.

**Licence position for this dataset.** Every source is a US government work in the public domain. NIST publishes SP 800-53, SP 800-171, SP 800-218 and the Cybersecurity Framework 2.0, with their OSCAL renderings in a public GitHub repository, and NIST's own position is that "Works authored by NIST employees are not subject to Copyright protection within the United States"; the Code of Federal Regulations is published by the Office of the Federal Register. NIST asks that its work be cited in its recommended form followed by "Republished courtesy of the National Institute of Standards and Technology", and each record carries that line, links back to the exact file it was cut from and names the publisher's own page for the document. A passage inside a NIST publication that is credited to a third party is outside NIST's grant: the parser reads only the publisher's own provision text and never the `links` blocks where other bodies' clause numbering sits. No text from SOC 2, ISO/IEC 27001 or PCI DSS appears anywhere in this dataset, because that text is sold under licence.
